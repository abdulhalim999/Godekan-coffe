# Работа с ветками

Модель простая, на две постоянные ветки и временные ветки под задачи.

## Постоянные ветки

| Ветка | Роль | Кто в неё пишет |
| --- | --- | --- |
| `main` | То, что сейчас у гостей на сайте. Всегда рабочая. | Только слияния из `develop` |
| `develop` | Собранные и проверенные фичи, следующий релиз. | Только слияния из `feature/*` |

Правило одно: **напрямую в `main` не коммитим**. Любая правка проходит путь
`feature/* → develop → main`. Так `main` остаётся тем, что можно выложить
в любой момент.

## Ветки под фичи

Заведены под задачи из раздела «Что дальше» в [README](../README.md):

| Ветка | Что в ней делается |
| --- | --- |
| `feature/api-integration` | Заменить `fetchMenu()` и `submitOrder()` на реальные запросы к бэкенду |
| `feature/menu-photos` | Фотографии блюд в карточках вместо орнамента (блок `.card__thumb`, 16 : 9) |
| `feature/online-payment` | Оплата картой при оформлении и статус заказа |
| `feature/table-booking` | Бронирование столика с выбором даты, времени и числа гостей |

Ветки созданы от `develop` и пока пустые — это подготовленные рабочие места.

## Как вести задачу

```bash
# 1. начать
git switch develop
git pull                      # если появится общий репозиторий
git switch feature/menu-photos

# 2. работать, коммитить небольшими шагами
git add src/features/menu-view.js
git commit -m "Меню: фотографии блюд в карточках"

# 3. подтянуть чужие изменения, чтобы слияние прошло чисто
git switch develop
git merge feature/menu-photos

# 4. когда набралось на релиз
git switch main
git merge develop
git tag -a v1.1.0 -m "Фотографии в меню"
```

Новая задача, которой нет в таблице:

```bash
git switch develop
git switch -c feature/короткое-имя
```

## Имена веток

- `feature/*` — новая функциональность;
- `fix/*` — исправление ошибки в `develop`;
- `hotfix/*` — срочная правка прямо от `main` (сливается и в `main`, и в `develop`).

Имя — латиницей, через дефис, по существу задачи: `feature/menu-photos`,
а не `feature/new` или `feature/abdul`.
